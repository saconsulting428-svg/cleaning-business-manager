# Home Haven 3D — v2 (real 3D building, Dream Home, challenges, contracts, properties)

`Home_Haven_3D.html` is the complete, runnable, single-file game (5.5 MB). Open it in any modern browser, or package it for Android (see `android/README.md`).

```
Home_Haven_3D.html   the game (generated by build/build3.py)
engine/              Three.js construction engine: procedural 3D models for all 71 parts, textures, world, thumbnails
build/               build script + the game-flow extensions that are patched into the original game
vendor/three.min.js  Three.js r160 (MIT), inlined into the HTML at build time
original/            the untouched original game you supplied (recoverable copy)
tests/               the Playwright scripts used to test the game (see docs/FEATURES_BUGS_TESTS.md)
android/             Capacitor 6 wrapper scaffold (NOT built/tested here, see android/README.md)
docs/                features, bugs fixed (with root causes), tests performed, known limitations
```

## Technology decision
The original architecture was kept and extended instead of migrating to Unity:

* **Puzzles stay on Phaser 3** (the seven puzzle scenes, their pre-rendered pieces, HUD, boosters, economy and story flow are unchanged except for the fixes listed in the docs).
* **The house / world is now real 3D (Three.js r160)**. The old Phaser isometric *sprite* world could not deliver a camera you can rotate, real lighting/shadows, upper floors you cut away, continuous roofs, per-property terrain themes or characters that walk through doors. Three.js runs inside the same HTML/Capacitor shell, so the single-file deliverable, the existing saves and the Android route are preserved.
* **Unity was not chosen**: it could not be built or tested in the environment this was developed in (no Unity/Android toolchain, restricted network), and nothing in the spec needed it. A Unity port would be a rebuild of everything; the data (`data_ext.js`: chapters, challenges, contracts, properties) and the part table are engine-independent and could be reused.

Saves are the same `localStorage` key (`homehaven3d_save`), version 5, migrated from v3/v4 (see docs).

## Rebuild
```bash
cd build
python3 build3.py            # -> ../Home_Haven_3D.html  (needs only Python 3; three.js is vendored)
```
The build patches `original/Home_Haven_3D.original.html` (string replacements that fail loudly if the original changes) and inlines `vendor/three.min.js` + `engine/*.js`.

## Running the tests
`npm i playwright` (Chromium), then e.g. `node tests/pz1.js ../Home_Haven_3D.html` from a directory where `../Home_Haven_3D.html` resolves (the scripts take the HTML path as argument, relative to the cwd). See `docs/FEATURES_BUGS_TESTS.md`.
